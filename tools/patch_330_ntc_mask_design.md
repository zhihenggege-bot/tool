# 330 内机 NTC 屏蔽位 —— 设计方案

> ## ✅ **已于 2026-09-23 实施（V10.15）**
> 落地记录与构建结果见 `调试记录_20260916.md` §54.11。
> **仍未烧录、仍未实机验证**（硬件不在身边）；§4 的 7 步验证一步都没跑。
> 下面 §1~§5 保留为设计依据与验证步骤，§3 的代码片段与实际落地一致。

## 0. 范围（2026-09-23 按用户要求收窄）

| | |
|---|---|
| **要改的板** | **只有 PSC330 内机**。316 外机**不动** |
| **要屏蔽的通道** | **只有 NTC0 / NTC1 / NTC2 / NTC3** 四路 |
| **不改** | 316 的 `NTC16bit.c`；330 的 NTC4~NTC11（见 §1.1） |

被屏蔽的四路：

| 通道 | 名称 | 显示寄存器 | 校准偏移 | "被需要"条件 |
|---|---|---|---|---|
| **NTC0** | 房间/回风温度 | `[511]` | `[495]` | `roomTemperatureNeeded` |
| **NTC1** | 送风温度 | `[510]` | `[494]` | `supplyTemperatureNeeded`（**制冷/制热下恒需要**） |
| **NTC2** | 新风温度 | `[512]` | `[493]` | `freshTemperatureNeeded` |
| **NTC3** | 预热后温度 | `[513]` | `[492]` | `postPreheatTemperatureNeeded` |

## 1. 要解决的问题

现场这四路 NTC **不一定全装**。不装的断线后：

```
NTC 断线 → SensorStatus[5+i]=1 → 5 秒后 SensorErr[i]=1（锁存）
  ├─→ xxxTempErr → ErrTotal++ → **Y05 综合报警吸合（[819]）**     ← 无门禁
  └─→ indoorSensorFault → IndoorSensorPartialStopFlag → 部分停机  ← 有门禁
```

现有三个看起来能用的开关**都不管用**（详见 `调试记录_20260916.md` §54.7.5）：

| 看起来像的 | 实际 |
|---|---|
| AI 通道使能位 `AiCfgEnable`（1229+ch*12+0） | 只管 AI0~AI4，NTC 路径**没有使能判断** |
| `[387] DebugBypassSensorSet` | 只旁路显示，**不影响报警/Y05** |
| `[388]` 台数豁免 | 只覆盖"不存在的外机"，且代价是**停掉那台外机** |

### 1.1 为什么不做 NTC4~NTC11

那八路是**蒸发温度**。屏蔽它们等于让固件拿一个假的常温去算过热度/蒸发低温保护 —— 压缩机还在跑的时候，这会把保护逻辑整个带偏。**风险远大于收益，且现场需求不涉及。** 本设计里 `NtcMaskSet(ch)` 对 `ch >= 4` **恒返回 0**，从代码上就屏蔽不了它们。

## 2. 地址选择

用**扫描法**找"代码里零引用"的地址（扫全部 `Parameter[数字]` 与 `Parameter[宏+数字]`，宏基址全展开 310 个）：

```
零引用地址(1~449) = 136,137,...,154, 189, 199, 208, 209, 258, 259, 269, 327
```

**取 `[136]`~`[139]`**（连续 4 个，对应 NTC0~NTC3），理由：

- 逐点表把它们标为"**保存参数但未找到明确宏名；按 min/max 可写**" ⇒ 在 EEPROM 区（`<500`）、可写、无人用
- 排除了计算下标批量访问：`Parameter[MAKER+j]`（`MAKER=78`，循环 `j<5`）只覆盖 78~82；`Parameter[HREST+i]`（`HREST=594`）覆盖 594~693；**都不碰 136~139**
- `<500` ⇒ 走 `ParamCanWriteFromHMI` 末尾的 min/max 分支，**无需改 modbus 白名单**

**备选**：单寄存器 4 位掩码（如 `[327] PowerFailRecoverModeSet`，逐点表标注"保留的旧恢复策略参数"）。省 3 个地址，但 MCGS 上要按位拆，**不推荐**。

## 3. 改动清单（**只改 330，共 3 处**）

### 3.1 `UserHead/User.h` —— 新增宏

```c
/* NTC 屏蔽：1 = 该路 NTC 不装/不检测 —— 断线不再置 SensorStatus、
   不再报故障、不再让 Y05 吸合。0 = 正常检测（出厂默认）。
   地址 136~139 为扫描确认的零引用段。
   ⚠ 只覆盖 NTC0~NTC3；NTC4~NTC11（蒸发温度）不可屏蔽，见设计文档 §1.1。 */
#define NTC_MASK_BASE              136
#define NTC_MASK_COUNT             4
#define NtcMaskSet(ch)             (((ch) < NTC_MASK_COUNT) ? \
                                    Parameter[NTC_MASK_BASE + (ch)] : 0)
#define NTC_MASK_PLACEHOLDER       250   /* 屏蔽时显示的占位值 = 25.0°C */
```

`NtcMaskSet(ch)` 用三元表达式：**`ch >= 4` 一律返回 0** ⇒ 蒸发温度那八路在代码层面就屏蔽不掉。

### 3.2 `UserSrc/user.c` —— `ParameterInit()` 里加量程与默认值

```c
{
    unsigned int ch;
    for(ch = 0; ch < NTC_MASK_COUNT; ch++)
    {
        Parameter_min[NTC_MASK_BASE + ch] = 0;
        Parameter_max[NTC_MASK_BASE + ch] = 1;
        Parameter_def[NTC_MASK_BASE + ch] = 0;      /* 默认不屏蔽 */
    }
}
```

### 3.3 `NTC16bit/NTC16bit.c` —— `Get_temp16()` 核心改动

在 `for(uint8_t i=0;i<NTCNum;i++)` 循环体**最前面**插入：

```c
for(uint8_t i=0;i<NTCNum;i++)
{
    /* ↓↓↓ 新增：屏蔽路直接给占位值，不置故障 ↓↓↓ */
    if(NtcMaskSet(i))
    {
        NTC[i] = NTC_MASK_PLACEHOLDER;
        SensorStatus[5+i] = 0;
        continue;
    }
    /* ↑↑↑ 新增结束 ↑↑↑ */

    if(IsNtcAdInvalid(NTC_AD[i]))
    {
        NTC[i] = 9999;
        SensorStatus[5+i]=1;
        continue;
    }
    ...（原有逻辑不动）...
}
```

**三个要点**：

1. **`SensorStatus[5+i] = 0` 必须主动清零，不能只 `continue`**
   `SensorStatus[]` 是跨扫描保持的全局数组。上一次扫描置的 1 会一直留着，
   `SensorErrCount` 继续累加，5 秒后照样报故障、照样吸 Y05。
   **这是整个补丁里唯一有陷阱的地方。**
2. 占位值给 `250`（=25.0°C）而不是 9999 —— 9999 会污染后续比较。
3. 循环仍遍历 `NTCNum`(12)，但 `NtcMaskSet` 对 `i>=4` 恒 0 ⇒ **NTC4~NTC11 行为完全不变**。

### 3.4 不需要改的地方

- **`ErrorCheck.c` 不用动** —— `SensorStatus[5+i]` 不置 1，`SensorErr[i]` 自然不置，Y05 和部分停机两条支路一起解决
- **`modbus.c` 不用动** —— 136~139 < `ParameterSaveSize`，走通用 min/max 校验
- **`DispAction.c` / `UserAction.c` 的显示强制不用动** —— `SensorStatus` 为 0，`if(... && SensorStatus[ch])` 不成立
- **316 完全不用动**

### 3.5 上位机侧

- **监控软件**：在「模式与设备配置」页新增一组「NTC 屏蔽」，4 个复选框（NTC0 房间/回风、NTC1 送风、NTC2 新风、NTC3 预热后）
- **MCGS**：4 个 0/1 开关通道，地址 **136~139**，16 位无符号

## 4. 验证步骤（改完烧录后）

| 步 | 动作 | 期望 |
|---|---|---|
| 1 | 清 `[136..139]` 全 0，拔掉 NTC0 | 5 秒后 `SensorStatus[5]`=1 → `SensorErr[5]`=1 → **Y05 吸合**（复现现状） |
| 2 | 脉冲 `[524]` 复位，`[136]` 写 1 | — |
| 3 | 观察 60 秒 | NTC0 显示 **25.0°C**（`[511]`，不是 9999） |
| 4 | 观察 60 秒 | `SensorErr[5]` **保持 0**；`ErrTotal` 不增；**Y05 (`[819]`) 保持 0** |
| 5 | 观察 60 秒 | `SysStep` 不受影响（无部分停机） |
| 6 | 把 `[136]` 写回 0 | 5 秒后恢复报警（说明屏蔽可撤销） |
| 7 | **对照**：拔 NTC4（不屏蔽），`[140]` 不存在 | NTC4~NTC11 的行为**必须与改动前完全一致** |

**判据只认寄存器与引脚**：`[819]`（Y05 显示）与 `io.h` 的 `output[5]`（GPIO ODR）——
**别拿 RAM 瞬态当翻转**（见"预热DO不吸合"那次的教训）。

## 5. 开放问题（需拍板）

1. **规格书没定义"不需要的传感器"这个概念**。屏蔽位属于**固件自加**（和 `[30]` 预热等待、`290/291` 调节周期同类）。要不要同步补进规格书？
2. **占位值选多少**？25.0°C 是个中性值。四路都是温度通道，屏蔽后若对应功能还在用，
   控制会拿 25°C 当真值 —— 所以**屏蔽前要先确认对应功能已关**（或接受这个假值）。
3. **要不要顺带把 Y05 那条支路也加门禁**（不报警 + 不部分停机，但不改显示）？
   那是另一种取向 —— 屏蔽位是"彻底不管这一路"，门禁是"管但不上报"。**建议只做屏蔽位**，语义更清楚。
