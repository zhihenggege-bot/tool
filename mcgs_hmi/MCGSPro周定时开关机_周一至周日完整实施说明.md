# MCGSPro周定时开关机完整实施说明

适用对象：第一次使用MCGSPro脚本的操作人员。

适用控制器：PSC330。

计划形式：星期一至星期日，每天两个开机时段，共14个时段。

## 1. 先纠正“PLC控制方式一直是普通”

PSC330源码中有四个不同含义的寄存器，不能混用：

| PSC330地址 | 建议MCGS变量名 | 读写 | 数值含义 |
|---:|---|---|---|
| 163 | `R0163_普通控制来源` | 读写 | 0=本地/HMI，1=远程开关，2=PLC |
| 165 | `R0165_定时模式使能` | 读写 | 0=普通控制，1=定时控制 |
| 714 | `R0714_当前控制方式` | 只读 | 0=本地，1=远程，2=PLC，3=定时 |
| 1388 | `R1388_定时运行目标` | 读写 | 0=要求停机，1=要求运行 |

源码实际执行关系：

1. 当165=0时，PSC330才根据163选择本地、远程或PLC控制。
2. 当165=1时，PSC330忽略普通开关来源，改为根据1388执行定时开关机。
3. 当165=1时，714应显示3，表示当前实际处于定时控制。
4. 进入定时模式不会自动把163改成2。163继续显示0、1或2都正常。

因此，“PLC控制方式一直是普通”有三种常见原因：

1. 画面显示框绑定了163。163是退出定时后的普通控制来源，不是定时使能。
2. 画面绑定了714，但状态显示只配置了0和1，没有配置`3=定时`，数值3被错误显示成“普通”。
3. 165没有真正写成1。必须看`R0165_定时模式使能`的设备读回值，不能只看按钮有没有按下。

正确画面至少同时显示：

- `R0163_普通控制来源`：观察退出定时后由谁接管。
- `R0165_定时模式使能`：确认是否进入定时模式。
- `R0714_当前控制方式`：确认当前实际控制来源。
- `R1388_定时运行目标`：确认定时脚本当前要求开机还是停机。

不要把165的标题再写成“PLC控制方式”。建议改成“定时模式使能”。

## 2. 功能原理

MCGSPro负责读取触摸屏时钟并计算当前是否在任意有效时段内：

1. 任意一个时段有效：计算目标为1。
2. 所有时段都无效：计算目标为0。
3. 脚本先确认165已经读回1，再把计算目标写到1388。
4. PSC330收到1388=1后，按固件正常开机顺序启动。
5. PSC330收到1388=0后，按固件正常关机顺序停止。

周定时不直接写Y点，也不直接启动风机、压缩机、阀门、加热器或加湿器。

不要用398代替1388。398是普通本地/HMI开关机命令，定时模式应由165和1388控制。

## 8. 第六步：建立4个总控制按钮

### 8.1 “启用周定时”

1. 放置一个标准按钮。
2. 按钮文字填写`启用周定时`。
3. 双击按钮并进入`脚本程序`。
4. 保持按下脚本为空。
5. 在抬起脚本中粘贴按钮脚本文件第二部分。

成功后应依次看到：

1. `bScheduleMasterEnable=1`。
2. `R0165_定时模式使能=1`。
3. `R0714_当前控制方式=3`。
4. `R1388_定时运行目标`跟随`nScheduleTarget`。

### 8.2 “退出定时并保持当前状态”

1. 放置一个标准按钮。
2. 按钮文字填写`退出定时并保持当前状态`。
3. 把按钮脚本文件第三部分放到抬起脚本。

它只把165改回0，不主动把1388改成0。

退出后由163设置的来源立即接管：

- 163=0：本地/HMI接管。
- 163=1：远程开关接管。
- 163=2：PLC输入接管。

因此，163为1或2时，退出定时后的实际开关状态可能立即跟随外部输入变化。

### 8.3 “停机并退出定时”

1. 放置一个标准按钮。
2. 按钮文字填写`停机并退出定时`。
3. 把按钮脚本文件第四部分放到抬起脚本。

正确过程：

1. 先写1388=0。
2. PSC330执行正常停机流程。
3. 709最终回到0。
4. 循环策略再写165=0。
5. 714从3变为163所选择的0、1或2。

### 8.4 “全部时段禁用”

1. 放置一个标准按钮。
2. 按钮文字填写`全部时段禁用`。
3. 把按钮脚本文件第五部分放到抬起脚本。

这个按钮只关闭14个时段。周定时总使能仍为1，所以循环脚本会计算1388目标为0并要求正常停机。

## 9. 第七步：安装1秒循环脚本

完整脚本文件：

`mcgs_hmi/MCGSPro周定时_全周14时段循环脚本.txt`

操作步骤：

1. 回到MCGSPro工作台。
2. 找到`运行策略`。
3. 双击现有的`循环策略`。
4. 如果工程没有循环策略，新建一个循环策略。
5. 把循环周期设置为`1000 ms`。
6. 在循环策略编辑区添加一个`脚本程序`构件。
7. 双击脚本程序构件。
8. 打开完整循环脚本文件。
9. 从第一行复制到最后一行。
10. 全部粘贴到循环策略的脚本程序中。
11. 检查工程中的PSC330设备名称。
12. 如果设备不叫`设备0`，用实际设备名替换脚本中全部`设备0`。
13. 点击`检查`、`语法检查`或`编译`。
14. 没有错误后保存。

完整循环脚本只能放一份。

不要同时在以下多个位置放置同一套写165和1388的脚本：

- 多个循环策略。
- 周定时窗口循环脚本。
- 主画面循环脚本。
- 后台启动脚本。

存在两套脚本时，两套目标可能互相覆盖。

## 13. 常见问题

| 现象 | 原因和处理 |
|---|---|
| 163一直为0 | 正常。163是普通模式来源，周定时不修改163 |
| “PLC控制方式”一直显示普通 | 改标题和绑定；165显示普通/定时，714显示本地/远程/PLC/定时 |
| 165=1但画面仍显示普通 | 检查显示对象是否绑定714，并增加`3=定时`状态 |
| 165始终写不成1 | 检查设备名、WriteP地址、串口通信和R0165设备连接 |
| 165=1但1388不变化 | 检查循环策略是否运行、周期是否1000ms、当前时段Enable是否为1 |
| Active不变化 | 检查触摸屏日期、星期和时间，以及输入框绑定变量 |
| 1388=1但机组不启动 | 检查709是否为0、710及消防、外部连锁和风机故障 |
| 到时反复写寄存器 | 检查工程中是否有两套循环脚本 |
| 时间相差一天 | 检查触摸屏系统日期和`!TimeGetDayOfWeek()`显示值 |
| 地址相差1 | 本项目脚本按0基地址；先用709与监控软件对比确认驱动地址方式 |

## 14. 正式投入前检查

1. 165显示名称必须是“定时模式使能”。
2. 714状态文字必须包含`3=定时`。
3. 163只用于显示普通模式控制来源，本脚本不得改写。
4. 全工程只能有一套脚本写165和1388。
5. 循环策略周期必须是1000ms。
6. 70个时段设置变量必须掉电保持。
7. Active、时钟和诊断变量不得掉电保持。
8. 所有按钮脚本只放在抬起脚本。
9. 1388只在目标变化时写，不每秒重复写。
10. 消防、外部连锁、风机和传感器保护继续由PSC330固件执行。
11. 正式使用前必须实体测试普通时段、跨午夜、星期日跨周一、启动中取消和HMI重启恢复。
