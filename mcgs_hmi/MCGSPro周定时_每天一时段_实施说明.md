# MCGSPro周定时：保留现有每天一组时间的画面

更新日期：2026-11-17。适配用户提供的 `星期一～星期日`、`open_hour_1～7` 等变量和PSC330 V10.64定时接口。本版是每天一个时段，不需要改成原说明中的每天两个时段。

屏幕的控制来源选择只提供两项，绑定330 `Parameter[163]`：0本地、1远程X02。定时仍单独设置，不作为来源选择的第三项。本地保留原手动／定时逻辑，X02不影响本地启停；远程时仅X02控制启停，本地按钮和定时目标不接管。旧PLC选项不放到新屏幕上。

`bWeeklyScheduleEnable = 1` 是屏幕周计划使能；`nWExit`、`nWPhase`、`nWZeroTicks`、`nWRetry`、`nWResult` 是脚本过程状态。这些按钮语句不选择远程／本地，也不直接启动负载。切到远程时，保存的星期、时间、总使能及退出任务均保留，循环策略暂停写165/1388，结果码为7。切回本地后重新同步，避免旧目标误启动。

## 1. 保留的画面和变量

星期选择仍使用原来的 `星期一`、`星期二`、`星期三`、`星期四`、`星期五`、`星期六`、`星期日`，0停用、1启用。开关机时间仍使用 `open_hour_1～7`、`open_minute_1～7`、`close_hour_1～7`、`close_minute_1～7`，编号1为周一、7为周日。

这些35个设置变量为MCGS本地数值变量，需要掉电保持。时间输入框只允许整数，小时0～23、分钟0～59，小数位设0。新增一个总使能 `bWeeklyScheduleEnable`，默认0，掉电保持；通过配套按钮启用或停机退出。

原来用来显示时间的字符变量，如 `当前时`、`星期一开机时`，可继续留给画面显示，但新循环脚本不再通过字符串比较来控制启停。`XINGQI`仍为数值变量。

## 2. 先连接六个设备变量

| MCGS变量名 | 330 Parameter下标 | 权限 | 含义 |
|---|---:|---|---|
| `R0163_控制来源` | 163 | 脚本只读 | 0本地、1远程X02；屏幕选择控件可写163 |
| `R0165_定时模式使能` | 165 | 读写 | 0普通、1定时 |
| `R1388_定时运行目标` | 1388 | 读写 | 0要求停机、1要求运行 |
| `R0700_系统状态` | 700 | 只读 | 10表示上电延迟 |
| `R0709_开关机步骤` | 709 | 只读 | 0停机、1启动、2运行 |
| `R0714_当前控制方式` | 714 | 只读 | 3表示定时控制 |

以上必须连接PSC330保持寄存器，不能仅创建成同名内部变量；均按16位无符号整数读取。脚本直接给连接变量赋值，不调用 `!SetDevice`。表中是Parameter下标，若驱动使用1基4x寄存器编号，163对应164，其余依次为166、1389、701、710、715；采用与现有已验证通道相同的地址方式，并对照监控软件确认709和714的读数。

设备连接变量使用设备读回作为初始来源，不设置HMI启动时自动向设备下载内部初值。其余新增内部变量按CSV创建；`nWExit`掉电保持，以便HMI重启后继续未完成的停机退出。`nWPhase`、`nWZeroTicks`等过程变量不掉电保持。

不再由定时策略写 `Keyboard_ONOFF`，也不写398、1386、故障复位524、163控制来源或任何负载输出。普通手动开关按钮可以保留，但普通控制应在退出定时后使用。

## 3. 安装顺序

1. 将MCGS工程另存为副本。
2. 停用原来给 `Keyboard_ONOFF` 赋值的整段定时循环策略，也停用其它写165/1388的旧定时脚本。全工程仅保留一套定时控制。
3. 按变量表补充缺少的变量。原变量存在则保留原名和保存的设置。
4. 将循环脚本全文放入“运行策略→循环策略→脚本程序”，周期1000ms。必须为全局循环策略，不能只在周定时画面打开时执行。
5. 新建“启用周定时”和“停机并退出周定时”两个按钮，把配套文件中各自那一段放入按钮抬起脚本。不要把两个按钮脚本连着复制到同一按钮。
6. 将第三段过程变量初始化放入HMI启动策略。它不清除星期选择、已保存时间、总使能或退出任务。
7. 临时显示 `XINGQI`、`nWTarget`、`nWResult`及165、1388、709、714，编译并检查是否有未创建变量。
8. 实际屏上核对星期：本版沿用原脚本约定，`$Week`为0周日、1周一至6周六。不能将这个约定直接套到另一个取星期函数。若屏上值不同，应先调整映射，不能直接投入定时。

## 4. 时段规则

采用“开始时刻≤当前时间＜结束时刻”。例如08:00～18:00，08:00目标为1，18:00目标变0；机组实际启动、停机还需执行固件顺序。

开始与结束相同表示该时段无效，不表示全天运行。结束早于开始表示跨午夜：周一22:00～06:00由“星期一”使能控制，可持续到周二06:00，即使星期二未勾选也应在凌晨继续运行。星期日跨星期一同理。时段重叠按“或”运算，只要任一时段仍有效就继续运行。

HMI在08:05重新运行，而当天时段为08:00～18:00时，会重新计算目标为1；不必等到下一天08:00。时段外重启则目标为0。启用日时间越界或时钟数值越界时，不允许发出新开机目标；已启用计划则将1388目标置0，显示101/102。周计划未启用且没有退出任务时不写设备。

## 5. 初始化、运行与退出

当前固件 `Switch.c` 的 `timerArmed` 需要先观察到1388=0，才能接受定时启动。脚本在首次接管停止中的机组时先清旧目标、进入定时模式，待165=1、714=3、1388=0且已离开上电延迟稳定3次循环，再发送时段目标；这是HMI初始化握手，不改变风机、压缩机的保护时间。写命令失败或读回不一致时，至少间隔5次循环再重试。

如果仅HMI重启，且设备反馈原本已经是定时启动中或运行中，脚本直接重新计算时段目标，不为初始化强制先停机。若设备处于关机过程，则按准备流程接管，固件等完全停机后再判断启动条件。

“停机并退出周定时”先保持定时模式并将1388置0，等709=0后才将165置0。退出任务优先于时间检查，错误时钟或错误设置不会阻断停机退出。

本地完成退出后恢复本地手动控制。若已切到远程，定时退出任务暂停，返回本地后继续；不能用“停机并退出周定时”按钮停止远程X02要求的运行。远程停机应断开X02。

切换163时固件清除上一来源的启停指令。若正在运行，按原正常停机顺序结束；新远程来源的X02已闭合时，等完全停机再启动。远程切回本地手动需重新按启动；切回已启用的本地定时则按脚本重新同步及当前时段判断。保护条件及启停顺序不被此来源选择绕过。

脚本不清故障、不复位保护、不强制负载启动。定时目标为1期间，故障解除或复位后能否重新运行仍取决于PSC330保护及启机逻辑；本版没有另加“每次故障后必须重新按周定时按钮”的锁定策略。

MCGS连接变量赋值可能先更新本地缓存，不能只凭赋值后的画面数值认定PLC已经执行。联机时要结合持续设备读回、714、709及实际状态判断。通讯中断后触摸屏不能保证向控制器送达停机命令，通讯故障保护仍由固件执行。

## 6. 结果码

| nWResult | 含义 |
|---:|---|
| 0 | 周计划未启用 |
| 1 | 初始化、进入定时模式或等待上电延迟结束 |
| 2 | 定时接口与当前时段目标一致，不代表负载已完成启动 |
| 3 | 正在写入当前时段目标 |
| 4 | 设备模式变化，重新同步 |
| 5 | 正在正常停机并退出定时 |
| 6 | 已退出定时，普通来源接管 |
| 7 | 当前非本地，周定时及退出任务暂停，保留设置 |
| 101 | 时钟数值越界 |
| 102 | 已启用日的时间设置越界 |

## 7. 验证范围与屏端验收

离线验证工具为 `tools/verify_weekly_single_period.py`，直接解释本次生成的循环脚本，核对整周分钟、跨日边界和接口命令顺序。它不连接串口、不改板上设置，不能代替MCGSPro语法编译或真实HMI通讯验收。

屏端至少检查：

| 场景 | 应观察到的行为 |
|---|---|
| 当天普通时段 | 到开始时1388=1，到结束时1388=0，709按固件顺序变化 |
| 开始等于结束 | 目标保持0 |
| 周一跨周二，周二未勾选 | 周二凌晨仍延续周一时段，到结束才停止 |
| 周日跨周一 | 正确跨周，结束时不晚一分钟 |
| 相邻日时段重叠 | 重叠处不多停一次 |
| 时段内/外重启HMI | 重新计算正确目标；原定时运行中的机组不被初始化停一次 |
| 控制器重启 | 上电延迟期间不发出运行目标1；初始化后由保护条件判断启动 |
| 启动中点击停机退出 | 1388先清0，709回0后再退出165 |
| 设置错误时点击停机退出 | 仍正常执行退出任务 |
| 故障及复位 | 定时脚本不写524，不绕过保护；记录故障解除后的真实恢复行为 |
| 通讯中断再恢复 | 不凭缓存判成功；恢复后确认165/1388/714和实际709 |
